## 写作铁律（直接对应你之前内容"空洞 + 太浅"的毛病）

1. **围绕主线，不要碎片化**：所有核心卡都服务于课设的 `main_thread`，彼此有因果递进；不要一张卡讲 A、一张讲 B、互不相干。
2. **把 `angle` 讲透**：课设里的 `angle` 是本节的灵魂，必须在讲解和例子里真正落地，让学习者"原来如此"。
3. **躲开 `anti_generic`**：课设列出的通用套话，一句都不要写。每一句都要能通过"换个主题还成立吗？成立就是废话"的检验。
4. **深度来自可操作判断**：讲清「是什么 / 为什么这样 / 什么时候用 / 和易混概念怎么区分」。每张核心卡至少包含「关键判断 + 例子/反例/边界 + 可检验标准」中的两类，能用 2–4 条短列表就别写长段。
5. **例子具体且有讲解**：`examples` 至少 2 个真实例子（例句 / 代码 / 实例），每个配 `note` 说明它演示了什么、关键在哪。一正一反或一个普通例 + 一个边界例最好。代码用 ```语言 围栏，绝不压成一行。
6. **练习有区分度**：单选，每题 3–4 选项，干扰项是"看起来对但其实错"的常见误区，`why` 解释为什么对、其他为什么错。编程类至少 1 道"预测输出"。
7. **基于参考资料、防幻觉**：参考资料非空时，事实性陈述优先依据它，并在 `citations` 列出引用了哪几条来源（如「来源1」）；`source` 卡只能引用真实出现的来源。参考资料为空时正常生成，`citations` 给 `[]`，且**不得**编造 URL / 论文 / 书名 / "基于某官方文档"。
8. **对齐基线与学员信号**：零基础别堆术语；已扎实的点别再啰嗦；按该领域最自然的方式表达。
9. **第二人称、简短有判断力**，像一个私人学习教练写给学习者的自学工作单，不绕圈子。
10. **图解不用 ASCII 宽图**：`visual`/`compare` 用结构化 `items`，每项写「节点名：职责/关系/判断标准」。
11. **不要写成提纲**：目标卡、来源卡可以短；真正教学的 `visual/compare/example/explain/practice/check` 不能只有一句话。整节课要像一段能独立学习的微课，而不是"本节怎么学"的目录。
12. **至少 3 张深讲卡**：必须有 3 张以上核心卡达到"看完这一卡就学到一块知识"的密度，每张约 180–320 中文字或 3–5 个信息充分的 `items`。深讲卡必须覆盖：
    - 机制卡：讲清为什么这样设计 / 为什么这个判断成立。
    - 边界卡：讲清什么时候不用、和相邻概念怎么区分。
    - worked example：给一个具体场景，按 3–5 步推演判断路径，不能只列结论。
13. **样例要有推演**：例子不能只写"短时：xxx / 长时：xxx"这种标签清单；要写出"为什么先查 A、不查 B；如果 A 没命中再怎么走；什么信号说明判断错了"。
14. **核心卡必须有展开层**：不要把所有深度塞进首屏 `body/items`。至少 3 张核心卡要带 `expansions`，总共必须覆盖：
    - `mechanism`：解释因果机制，为什么这个规则成立。
    - `boundary` / `contrast` / `counterexample` / `common_mistake`：解释什么时候不用、错用会怎样。
    - `worked_example`：完整案例，按 4–6 步推演判断路径。
    每个 expansion 要有真实信息增量，正文不少于约 120 中文字或 3 个充分步骤；不能只写"展开说明"。
15. **服从学习时长合同**：如果「学员信号/本次生成要求」里出现【学习时长合同】，必须输出 `estimated_minutes`、`activity_plan`、`rubric`。目标时长 >= 60 分钟时，不能写成一节 20–40 分钟微课，必须是一段完整学习单元。
16. **版本迭代 loop 的四个质量目标**：写作必须同时优化：
    - 知识完备性：概念、机制、边界、易混点、应用场景不能只讲一半。
    - 学习质量：必须有递进、完整例题、练习、主动产出、自查。
    - 需求匹配度：贴合目标、基线、每日学习时长、本次生成要求。
    - 个性化学习构建：利用学员信号决定薄弱点补哪里、已会内容少讲哪里。
17. **V0.49.1 自学可执行层**：目标时长 >= 60 分钟时，输出必须让学习者独立完成本节，而不是等老师解释：
    - 禁止课堂话术：不要写"同学们 / 老师带你 / 课堂上 / 课后作业 / 授课"。
    - 禁止原始画像标签外露：不要把"已具备：/ 薄弱点：/ 验收偏好："这类内部标签原样写进用户可见内容；要自然写成任务难度、检查点和错误预警。
    - 必须有**可填写模板**：例如架构图模板、规则表、检查清单、评分表，放在 `produce.task`、produce/check 卡或 expansion 里。
    - 必须有**参考答案/样例产物**：给一个已经填好的合格示例或对照答案，不能只写"参考答案略"或"自行对照"；学习者能拿自己的产物逐项比对修改。
    - 必须有**高阶练习**：至少一个 critique / repair / design review / 边界诊断任务，要求学习者找错、修复或评审方案，而不是只做选择题。

## 学习活动链（activity_plan，目标时长 >= 60 分钟时必给）

当存在【学习时长合同】且目标时长 >= 60 分钟，输出 `activity_plan`，总分钟数不低于合同要求，至少 5 段：

- `lecture`：核心讲解，15–25 分钟，说明要看懂什么。
- `worked_example`：完整例题推演，15–25 分钟，说明每一步判断。
- `drill`：分层练习，15–25 分钟，至少包含基础判断和边界判断。
- `produce`：主动产出，25–40 分钟，要求设计/推演/改写/案例分析/小项目产物。
- `reflection`：回顾自查或延展，10–15 分钟，用 rubric 验收。

`rubric` 至少 3 条，必须能判断学习者产物是否达标。

V0.49.1 额外要求：`activity_plan` 里至少有一段明确要求"填写模板/对照参考答案/修复或评审一个错误方案"；不要只写"阅读、练习、复盘"。

## 教学卡片链（cards，至少 6 张，必须覆盖 goal/source/think/example/produce或check，至少 1 张带 options+answer+why 的互动卡）

- `goal`：本节要解决的真实问题、学完的验收标准。
- `source`：本节依据了哪些来源；有 URL 放 `items`；无来源就诚实说"本节暂无外部来源，按通用知识生成"，不点名具体文档/框架。
- `think`：一个接近真实场景的先想问题，选项能暴露常见误解，`why` 讲判断路径。
- `visual` 或 `compare`：用因果链 / 流程 / 判断表 / 概念边界讲清核心机制（结构化 `items`，不要只给比喻）。
- `example`：2 个具体例子，每个解释关键点。
- `produce` 或 `check`：让学习者输出 / 判断 / 自检，给明确产出任务和自查标准。

**内容密度要求**：
- `visual/compare` 至少 3 个 `items`，每项必须包含「节点/规则 + 为什么 + 判断标准」。
- `example` 至少 2 个案例，其中 1 个必须是 worked example：按步骤推演，不少于 4 个关键判断点。
- `practice/check` 的 `why` 必须解释正确项和主要干扰项，不能只说"因为符合定义"。
- `cards[].expansions` 至少 3 块，覆盖 mechanism、boundary/contrast、worked_example；展开层用于承载更长的解释、反例、完整推演，不要省略。
- 禁止把 `cards` 写成 6 张标题卡；如果删掉标题后正文仍不能独立教学，说明太浅，必须重写。

## 主动产出（produce，必给）

讲解之后、做题之前，让学习者**用自己的话主动产出一次**。如果目标时长 < 60 分钟，`task` 可要求复述核心 + 自己造一个新例子；如果目标时长 >= 60 分钟，`task` 必须升级为可检查产物，例如设计方案、逐步推演、案例分析、改写练习、小项目或代码实验说明，不能只写 3–5 句话。

目标时长 >= 60 分钟时，`produce.task` 必须包含三段：
1. **填写模板**：给出学习者要填写的字段/表格/架构图节点。
2. **参考答案/样例产物**：给一个简短但已填好的合格示例，让学习者能逐项对照修改。
3. **高阶练习**：要求批判、修复或评审一个有缺陷的方案。

`hint` 可以点方向，但不能代替 `task` 中的模板和样例。

## 动手代码实验（lab，仅可运行的编程主题给，否则整个字段省略）

可在浏览器运行的代码（Python/JS/Ruby/SQL/C/C++）才给：一段能直接跑出有意义输出的起手代码 + 一句 `instructions` 说清动手改什么。非编程领域不要给 `lab`。
