执行判断

先明确方向，再看技术清单

V0.53 不应扩 scope；V0.54 应把“画像 → 深度教学 → 学习证据”接成闭环。 现有架构最值得保留的是“确定性规则优先、LLM 只处理语义重活、低置信进入复核”。最需要修复的是不同入口行为漂移、上下文缺少信任/预算合同、运行证据无法用同一 ID 回放。

当前控制链

模型只是其中一个执行组件

01
前馈目标、画像、Memory、RAG、时长合同
02
执行固定/动态 Workflow 与模型路由
03
确定性验证结构、DAG、质量门、状态守卫
04
语义验证Rubric evaluator、Critic、人工抽样
05
持久反馈Evidence、学习结果、推荐、重规划

做得好的地方

这些是后续演进必须保留的资产

技术分层克制

  • 掌握度、调度、阶段闸门、推荐和重规划尽量使用确定性代码。
  • LLM 只承担出题、开放题评分、路径大纲和教学写作等语义重活。

V0.53 证据链完整

  • Assessment、Response、ScoreEvidence、AbilityProfile 保持同一身份。
  • 低置信追加题、异议和双人人工门避免模型自证正确。

内容不是单次 Prompt

  • 检索、课设、写作、确定性质量门、Critic、bounded revise、best 保留已成链。
  • 后台任务、旧缓存升级和失败不覆盖好缓存具备生产形态。

学习 Loop 已闭合

  • 答题和产出进入掌握度、Memory、SM-2、推荐与重规划。
  • 路径调整必须确认，可拒绝、可撤销，不把 LLM 建议直接落地。

七域成熟度

绿色不是“无需改”，而是主链已经成立

域状态现有优势主要缺口下一步
模型与 Prompt部分闭环chat/reasoner、解析、超时、fallback内容 Prompt 版本与显式容灾不足先接 run/eval，再优化缓存
Context部分闭环按场景注入 RAG、信号、时长合同无预算、裁剪记录、信任分区、压缩ContextSnapshot
Memory基础可靠作用域、来源、确定性派生、删除缺 provenance/confidence/expiry/conflict补治理，不存流程
Tool / MCP地基可用13 工具、访问守卫、stdio MCPWeb/MCP 运行合同不一致统一 application service
Workflow / Loop主链较强bounded loop、推荐、重规划、阶段闸门重启后只能整轮重试安全 checkpoint
Eval / 观测能看见398 tests、V0.53 Eval、Release Loop、反馈、trace缺统一 run_id 与内容人工基准Evidence Plane
安全 / 运行时Web 强、Agent 弱鉴权、限流、Secure Cookie、导出删除通用 Prompt injection 隔离和工具审批不足Agent 通道单独发布门

V0.54-M4
