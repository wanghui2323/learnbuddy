任务完成定义（DoD）

一个任务标记为 Done，至少满足下面这些条件。
实现完成

代码或文档改动已经覆盖目标，不是只讨论未落地。

有验证

`core/` 改动看测试，`web/server` 改动看浏览器或接口实测。

有回退

LLM 相关能力必须有用户能看见的降级路径。

文档同步

开发结束后更新主文档和 HTML 入口页。

固定更新流程

以后每轮开发结束，建议按这个顺序更新。
顺序动作
1更新 `03-开发方案与计划.md`，把需求、技术、进度、计划写准
2同步 `工作台.html`、`文档中心.html`、相关专题 HTML 页
3如果涉及重大设计决策，再更新 `SPEC.md` ADR
4如果只改协作规则，再更新 `04-进度管理.md`
简单记忆：主文档先改，HTML 后跟；决策进 ADR，规则进协作机制。

HTML 文档站规则

为了避免“顶部 banner 跳来跳去”，所有 HTML 页面以后都按同一套规则维护。
项规则
一级导航固定为 `文档中心 / 工作台 / 需求方案 / 技术方案 / 架构总览 / 协作机制 / 主方案`
一级导航职责只做页面级跳转，不承载页内锚点、系统入口或一次性操作
当前页识别当前页必须高亮，帮助用户始终知道自己在哪一层
二级快捷操作统一放在 hero 区或正文，例如“开发计划”“打开产品”“打开系统”
主文档关系HTML 页不单独维护真相源，只负责更清晰的查看和图示表达
记忆方式：顶部是站点层，正文是页面层；一级导航固定，二级动作下沉。

新增页面模板

以后如果再新增 HTML 页面，建议按这个最小模板走，避免结构再次发散。
区块要求
Topbar复用固定一级导航，顺序不改，只高亮当前页
Hero放页面定位、当前摘要、二级快捷操作
正文按“总览 → 结构 → 细节 → 支撑信息”组织
页脚说明该页角色，以及与 Markdown 真相源的关系

常见风险与处理原则

这些是最容易把项目带偏的地方。
风险处理原则
范围蔓延先回到主文档确认当前阶段任务，避免同时做太多层级的事
文档漂移发现冲突时以 `03` 主文档为准，再反向同步 HTML 和专题文档
看似对但没验证先补测试、截图、接口验证或真实链路验证
同一问题连改两次还错停下，收敛问题和范围后再继续
