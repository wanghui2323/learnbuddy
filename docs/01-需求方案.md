## 1. 一句话定位

**把"个性化学习路径生成"做成一个领域无关的可复用引擎**——任何人用自然语言说出学习需求，10–30 分钟对话后得到一条量身定做、可执行、带考核与反遗忘机制的 4–24 周学习路径。

- **元目标**：将作者本人 dogfood 4 个月验证过的 LearnBuddy 方法论（来自 `AI技术学习空间`，历史名 iTutor）抽象为通用产品。
- **不限领域**：语言 / 编程 / 学科 / 营养 / 写作 / 考研 / 职业转型……皆可。
- **首个对外 demo 场景**：日语 N3 备考 3 个月（跳出 AI/技术圈，验证通用性）。

## 2. 问题陈述

### 2.1 产品缺口（来自真实使用反馈）

V0 跑通后，用户使用时明确指出当前学习路径**"没有学习的细节和考核性，以及用户画像和学习评估"**。拆解为 4 个产品缺口：

| 缺口 | 现状 | 影响 |
|---|---|---|
| **P-缺口1 学习细节不足** | 周计划是写死的时间段模板，与领域无关（学日语和学编程排出来一样）| 计划"看着对"但不可直接执行，缺具体资源/量化/验收 |
| **P-缺口2 无考核性** | 没有任何测验机制 | 用户无法验证学没学会，路径变成"纸上计划" |
| **P-缺口3 无用户画像** | 只有一句 `baseline_summary` 文本 | 系统不"懂"用户，无法对靶弱项 |
| **P-缺口4 评估未闭环** | 评估器代码已写但游离在运行路径外 | 核心差异点（即时基线评估）没真正发挥作用 |

### 2.2 工程缺口（来自代码复审）

| 缺口 | 现状 | 影响 |
|---|---|---|
| **E-缺口1 运行环境不可用** | `.venv` 在 iCloud 同步目录，启动卡几分钟 | 系统几乎无法在本机正常起服务 |
| **E-缺口2 并发阻塞** | 同步 LLM 调用塞在 async 事件循环里 | 单连接卡死拖垮整个 server |
| **E-缺口3 无超时保护** | 流式无首 token 超时 | LLM 卡住时连接永久挂起 |

> 详见 [02 技术方案 · 技术债登记](./02-技术方案.md#8-已知技术债登记)。

## 3. 目标用户与场景

### 3.1 目标用户

- **主用户**：有明确学习目标、愿意投入 4–24 周、需要"被结构化安排 + 被督促 + 被考核"的自学者。
- **典型画像**：备考者（语言/考研）、转型者（职业切换）、技能提升者（编程/写作/设计）。

### 3.2 核心场景（用户旅程）

1. **进入** → 看到对话首页，AI 教练暖场提问。
2. **对话** → 8–15 轮，AI 挖掘目标、现场出题做基线评估、盘点时间、给 3 选 1 路径方案。
3. **确认** → 用户选定方案，AI 触发生成。
4. **生成** → 得到完整学习路径（蓝图 + 详细周计划 + 学习手册 + 考核体系 + 愿景契约）。
5. **执行**（V1）→ 按周计划学习，每周做 6 关自检，触发反遗忘复习。
6. **评估**（V1）→ 每日小测 / 周章考 / 月度大考，画像随之更新，路径自动对靶调整。

### 3.3 需求能力地图

这不是一个“聊天框 + 几个页面”的产品，而是一个分层学习系统。需求结构如下：

```text
用户入口层
├─ 对话 onboarding
├─ 学习路径页
├─ 学习空间 / 今天一起学什么
└─ 学练 / 学情 / 自检

学习闭环层
├─ 即时基线评估
├─ 个性化路径生成
├─ 每日推荐 / 反遗忘复习
├─ 周回测 / 月度大考
└─ 动态重规划 / 节奏调整

长期陪伴层
├─ 个人记忆
├─ 偏好与弱项沉淀
├─ 主动提醒
└─ 跨任务复用

运营与商业化底座
├─ 注册登录 / 手机号绑定
├─ 支付 / 订单 / 回调
├─ 积分账户 / 积分流水 / 赠送积分
└─ 订阅权益 / 个人助理升级模式
```

### 3.4 用户旅程闭环图

```text
进入产品
  ↓
对话澄清目标 / 时间 / 约束
  ↓
即时基线评估（独立完成 vs AI 协作）
  ↓
生成个性化学习路径（master / W1 / 学习手册 / 契约）
  ↓
进入学习空间执行今日任务
  ↓
每日小测 / 周自检 / 周回测 / 月度大考
  ↓
画像、记忆、掌握度更新
  ↓
推荐 / 重规划 / 提醒
  └──────────────→ 回到下一轮学习
```

### 3.5 关键需求模块说明

| 模块 | 用户看到什么 | 系统必须做到什么 | 价值 |
|---|---|---|---|
| 对话引导 | 不是直接填表，而是被逐步问清目标、时间、基础 | 把开放式需求收敛成结构化参数包 | 降低表达门槛 |
| 即时基线评估 | 当场被测出“自己会什么、借助 AI 会什么” | 题目、回答、判分、画像要闭环 | 形成差异化 |
| 个性化路径 | 看到的是按自己情况生成的学习路径，不是模板 | 路径必须能消费画像与约束 | 让计划真的可执行 |
| 学习执行 | 进入学习空间后每天知道学什么 | 提供今日任务、复习、学练、学情 | 让用户持续留下来 |
| 自检与考核 | 不只是“学了”，而是“知道会没会” | 每日、每周、每月都有可回流数据 | 建立反馈回路 |
| 个人记忆 | 系统越用越懂你 | 偏好、弱项、节奏、背景长期沉淀 | 形成长期陪伴感 |

## 4. 核心价值主张 / 差异点

> 这些是"砍了就和普通 ChatGPT 没区别"的核心，不可妥协。

| # | 差异点 | 说明 |
|---|---|---|
| **D1 即时基线评估** | LLM 现场为领域出题，**双坐标系**（独立完成 vs AI 协作完成）区分"会做"与"借助 AI 能做" |
| **D2 个性化路径** | 不是通用模板，按用户目标/时间/基线/画像生成对靶路径 |
| **D3 反遗忘 5 机制** | micro-review / 间隔重复 / 周回测 / 月度雪球 / 解释关延迟 |
| **D4 6 关自检 + R 规则** | 每周自检 6 维度，自检不过自动触发节奏调整（R1–R10）|
| **D5 考核闭环** | 每日小测 / 周章考 / 月度大考，结果回流画像 |
| **D6 个人记忆系统** | 跨会话/跨学习任务沉淀"懂你"的记忆（画像演进 / 偏好 / 错题弱项 / 行为 / 背景），**越用越个性化**——详见 §7 |

> 原则：**先做"让 V0 更稳"，再做"让 V0 更深"，最后做"让 V0 更大"。**

- ✅ 对话引擎（system prompt + GENERATE 标记 + SSE 流式）
- ✅ 个性化生成器（参数包 → 5 件套：meta / master / W1 / 学习手册 / 愿景契约）
- ✅ FastAPI 服务 + 对话首页 + 实例展示页
- ✅ 88 个单元测试

### 5.2 V0.5（产品本质补完 · 本轮重点）

> 对应 §2.1 的 4 个产品缺口 + §2.2 的 3 个工程缺口。

| 模块 | 需求 | 对应缺口 |
|---|---|---|
| **稳定性修复** | venv 移出 iCloud / async 不阻塞 / 首 token 超时 | E1/E2/E3 |
| **评估闭环** | 把 evaluator 接进对话流，LLM 现场判分 | P4 |

| **个人记忆（预埋）** | `UserMemory` schema + 评估/学练后写入画像与偏好/弱项 | D6（§7）|

### 5.3 V1（产品成型 · 工程化与多租户）

| 优先级 | 项 |

| 项 | 说明 |

## 6. 多端策略与手机端提醒

> web 解决"学得深"，手机解决"不掉线"。**经核实微信规则后定调（见 6.2）：手机端职责极简——只负责"准时把人叫回来 + 一键跳回 web"，不在手机上重做学习，因此零安装门槛。**

### 6.1 双端分工

| 端 | 定位 | 承载 | 形态特征 |
|---|---|---|---|
| **Web（主动深度学习场）** | 学得深 | 路径生成对话 / 学练单元（讲解+练习）/ 学情面板 / 资料 / 6 关自检 | 大屏、长时段、专注 |
| **手机端（提醒触点）** | 准时叫回来 | 每日学习提醒 + 一键深链跳回 web | **零安装** · 通知驱动 |

> 原则：**手机端不重做学习，只做"提醒 + 导流回 web"**。重活全在 web。

### 6.2 关键判断：微信生态能不能做"个性化自提醒"？（结论：不能，故不硬做）

作者公众号为**订阅号**。经核实微信官方规则（2026），订阅号做提醒有三个硬伤，**结论是把提醒与公众号彻底解耦**：

| 限制 | 事实 | 后果 |
|---|---|---|
| **无个性化主动推送** | 订阅号没有模板消息 / 订阅通知 API；只有"每天 1 条群发"（统一文案）+ 被动回复（用户先互动）| 做不到一对一定时个性化提醒 |
| **群发占用文章名额** | 群发 **1 条/天**，与公众号发文章共用同一个每日唯一名额 | 发提醒 = 当天发不了文章，抢内容主业资源 |
| **群发面向全体粉丝** | 群发发给**所有**关注者，含大量非学习用户 | 天天推学习提醒 = 打扰 + 掉粉 |

> 能做个性化主动推的只有：认证服务号（需企业资质，个人申请不了）/ 小程序订阅消息（长期订阅教育类目基本申请不到，只能一次性订阅）。**均不符合"简单 + 低成本 + 不打扰"。故 V1 提醒不走公众号。**

### 6.3 选定方案（V1）：PWA + Web Push（自愿开启）+ 邮件兜底

> 把提醒做成 **web 应用自身的能力**——给现有 web 加一个"开启提醒"开关，不引入新平台、不碰公众号。

| 环节 | 做法 | 个性化 / 触达 |
|---|---|---|
| **开启** | 用户在 web 点"开启每日提醒"，授权浏览器通知（**仅自愿者**）| 只触达真实用户，无打扰 |
| **推送** | 每日定时 Web Push 个性化提醒（今日任务 + 到期复习）→ 点击跳回 web | ✅ 个性化、免费 |
| **兜底** | 未授权 / 不便用 Web Push（如部分 iOS）的用户 → **邮件每日 digest** | ✅ 全平台、零门槛 |
| **落地** | 提醒点开 → web 个性化今日页完成学练 | ✅ |

> 价值：只给自愿用户（天然解决"发给不该发的人"）、个性化、免费、**完全不碰公众号**、零安装。
> 唯一代价：iOS 用户需"添加到主屏"才能收 Web Push（一次性操作）；覆盖不到的用邮件兜底。

### 6.4 公众号的角色：内容与拉新，不做提醒

- 公众号保持**内容主业**，每日唯一群发名额留给文章。
- 偶尔写文章介绍产品、把粉丝**转化为产品用户**（拉新 / 营销），而非当每日提醒管道。

### 6.5 升级路径（数据驱动，不预先做）

- 国内 Web Push 到达不稳 / 要更好的原生通知体验 → **小程序 + 订阅消息**（V1.5）。
- 离线碎片学练：PWA 天然支持离线缓存；如需更强体验再评估小程序 / 原生（V2）。

### 6.6 手机端非目标

- ❌ V0.5 不做任何手机端（只预埋接口与字段）。
- ❌ **不用订阅号群发做每日提醒**（占文章名额 + 打扰非用户）。
- ❌ 不为个性化推送去办企业资质 / 做小程序（V1 不做，留作数据驱动的升级项）。
- ❌ 手机端不重做学习（只提醒 + 导流回 web）。

## 7. 个人记忆系统（越用越懂你）

> 这是 D6 差异点的展开。**画像（§5.2）回答"你现在水平怎样"，记忆系统回答"你是个什么样的学习者"**——它跨会话、跨学习任务长期沉淀，让系统越用越个性化，是 LearnBuddy 从"一次性生成器"走向"长期学习伙伴"的关键。

### 7.1 记忆 ≠ 画像（先划清边界）

| | 用户画像（UserProfile）| 个人记忆（UserMemory）|
|---|---|---|
| 范围 | 单个学习任务内 | **跨任务、跨会话、长期** |
| 内容 | N 维能力 × 双坐标评分 | 偏好 / 错题 / 行为 / 背景 / 画像演进史 |
| 更新 | 评估/考核后 | 每次学练、对话、打卡后增量沉淀 |
| 作用 | 本路径对靶弱项 | 让"下一次生成 + 日常教练"都更懂你 |

### 7.2 记忆的 5 层（存什么）

| 层 | 记什么 | 喂给谁 → 怎么变个性化 |
|---|---|---|
| **M1 画像记忆** | 各能力维度随时间的演进轨迹 | 生成器：知道你哪些在涨、哪些卡住 |
| **M2 偏好记忆** | 学习风格/节奏/时段/形式偏好（爱例子、嫌长文、晚上学）| 内容生成 + 教练语气：按你喜欢的方式讲 |
| **M3 错题/弱项记忆** | 反复错的点、易混概念 | 间隔重复 + 出题：优先重练你的弱项 |
| **M4 行为记忆** | 完成率、连续打卡、掉线信号、卡壳位置 | 每日推荐：节奏调整、及时干预流失 |
| **M5 背景/事实记忆** | 目标、Deadline、职业背景、跨领域线索（学日语的你也是开发者）| 全局：举例贴合你的背景，跨任务复用 |

### 7.3 怎么"越用越懂"（记忆闭环）

```text
每次学练/对话/考核/打卡
   ↓  写入：LLM 抽取「记忆增量」（这次暴露了什么偏好/弱项/行为）
个人记忆库（结构化，按层存储）
   ↓  定期：记忆巩固（合并去重、淘汰过期，防膨胀）
   ↓  读取：生成路径 / 每日推荐 / 教练对话前，召回相关记忆注入 prompt
更懂你的下一次输出 → 用户反馈 → 再写入（正循环）
```

### 7.4 透明可控（信任前提）

- 用户可**查看 / 编辑 / 删除**自己的记忆条目（"记忆面板"），不做黑箱。
- 记忆只服务个性化，不外泄、不跨用户共享。

### 7.5 分期

| 阶段 | 记忆系统动作 |
|---|---|
| **V0.5** | 预埋 `UserMemory` schema + 写入路径：评估/学练后把画像与明显偏好/弱项落库（单用户、JSON）|
| **V1** | LLM 记忆抽取 + 召回注入（生成/教练 prompt 带"关于这位学习者"段）+ 记忆面板（查看/编辑）+ 跨任务复用 |
| **V2** | 向量记忆（语义召回）+ 长期巩固（"记忆雪球"）+ 累积 N 周行为重写 system prompt |

### 7.6 记忆系统非目标

- ❌ V0.5 不做 LLM 自动抽取，只存结构化的画像/偏好/弱项（规则写入）。
- ❌ 不做跨用户的"群体记忆"/推荐（只服务本人个性化）。
- ❌ 不无限堆记忆——必须有巩固/淘汰，防 prompt 膨胀与成本失控。

## 8. 账户与商业化需求（补充）

> 这部分是当前新增的高优先级需求，目的不是“先赚钱”，而是把产品正式运营所需的账号、支付、权益和升级模式一次定义清楚。

### 8.1 用户模式分层

未来面向用户提供两种模式：

| 模式 | 定位 | 核心能力 | 收费方式 |
|---|---|---|---|
| **标准学习模式** | 默认模式 | 路径生成、学练、学情、推荐、复习、基础提醒 | 免费或基础订阅 |
| **个人助理模式** | 升级模式 | 托管的专属学习助理、长期记忆、主动提醒、主动复盘、跨端联动、IM 对话入口 | 用户自行选择开通，额外收费 |

### 8.2 账号体系补充

| 需求 | 说明 | 优先级 |
|---|---|---|
| 手机验证码注册登录 | 降低注册门槛，适配移动端转化 | P0 |
| 手机号绑定 | 支撑后续支付、消息触达、找回与风控 | P0 |
| 多登录方式并存 | 当前账号体系与手机号登录并存，避免强迁移 | P1 |

#### 手机验证码登录前置依赖

| 前置项 | 说明 |
|---|---|
| 短信服务商 | 需要稳定短信通道、模板、签名和成本测算 |
| 登录风控 | 需要限频、验证码有效期、设备/IP 异常控制 |
| 绑定流程 | 需要定义新注册、老用户绑定、重复手机号冲突处理 |
| 用户协议与隐私 | 需要补手机号采集、用途与安全说明 |

### 8.3 支付与积分体系

当前明确商业化原则：

- 用户侧计费单位是 **积分**，不是 token
- token 只作为系统内部成本核算，不直接暴露给用户
- 支付买到的是积分或套餐权益，再由积分驱动学习服务消耗
- 系统必须支持 **赠送积分**，用于拉新、补偿、活动、试用和运营激励

| 能力 | 需求说明 | 优先级 |
|---|---|---|
| 支付能力 | 支撑标准权益购买、升级模式开通、后续套餐销售 | P0 |
| 积分账户 | 每个用户有积分余额、变动记录、来源与用途 | P0 |
| 积分赠送 | 支持后台赠送、活动赠送、补偿赠送 | P0 |
| 积分扣减 | 明确什么行为消耗积分，支持可解释的流水 | P1 |
| 订阅 + 积分混合收费 | 个人助理模式可结合订阅和积分设计 | P1 |

#### 支付前置依赖

| 前置项 | 说明 |
|---|---|
| 支付通道 | 需要明确微信支付、支付宝或聚合支付策略 |
| 商品体系 | 需要先定义积分包、基础套餐、升级订阅的商品结构 |
| 订单与回调 | 需要幂等订单号、支付回调验签与重复通知处理 |
| 权益发放 | 需要支付成功后的积分/订阅权益幂等发放 |
| 退款与补偿 | 需要明确退款时积分回收和补偿逻辑 |

### 8.4 与产品模式的关系

- 标准学习模式可以主要按“基础订阅 + 部分积分消耗”设计
- 个人助理模式更适合按“升级订阅 + 积分包”设计
- 积分体系既要能覆盖真实成本，也要保留运营灵活性，不能和 token 1:1 对用户直出

### 8.5 商业化链路图

```text
用户注册 / 登录
  ↓
绑定手机号
  ↓
选择商品
  ├─ 基础订阅
  ├─ 积分包
  └─ 个人助理升级模式
  ↓
创建订单
  ↓
支付成功 / 回调验签
  ↓
发放权益
  ├─ 积分账户入账
  ├─ 订阅生效
  └─ 升级模式开通
  ↓
在 LearnBuddy 主系统内消费权益
```

### 8.6 账号、支付与产品边界

| 问题 | 当前结论 |
|---|---|
| 支付发生在哪 | 发生在 LearnBuddy 主系统，不发生在 IM 或 OpenClaw 侧 |
| 谁维护账本 | LearnBuddy 账户、订单、积分、权益统一维护 |
| Agent 能不能单独收费 | 不能单独有一套账，只能消费主系统发放的权益 |
| 用户如何理解价格 | 对外统一理解为订阅、积分和升级模式，不暴露 token |
| 商业化是否改变主产品 | 不改变。商业化是底座，不是替代学习闭环 |

## 10. 非目标（明确不做，防止无底洞）

- ❌ **课程内容生产**：不是 Coursera，不卖课、不做内容。
- ❌ **社交 / 师生匹配**：不是教育机构，不做撮合。
- ❌ **AI 替你学**：拒绝"帮你做作业"，LearnBuddy 给的是脚手架不是答案。
- ❌ **强实操领域**（钢琴/烹饪/化学实验）：V2 才考虑硬件/视频反馈。
- ❌ **4 周以内速成**：节奏下限 4 周。
