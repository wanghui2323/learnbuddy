用一套通用设计规范约束 LearnBuddy 的每次产品迭代

这不是某个版本的需求，而是跨版本设计准则。它定义 LearnBuddy 的产品调性、信息层级、组件规则、AI 状态、图片资产和验收方式；后续每次迭代都要检查是否遵守，具体页面改造再单独立版本。

规范目标与当前实现 · 2026-09-06

本页描述目标准则，不表示所有页面已完成统一。当前 对话页、学习空间等仍在各自的 :root 定义 teal / amber / paper；common.css负责 toast、加载和响应式等公共状态。尚无独立 web/design-tokens.css。可在学习地图查看实际色值与页面映射。

需求背景

内容质量已经进入受控流水线，但视觉承接仍像多轮迭代拼起来的原型。

  • 页面级内联样式多，组件语言不统一。
  • 暖纸底、卡片、按钮、状态色缺少统一规则。
  • 登录页、学习空间、路径页和学练页没有共同的品牌气质。
  • 图片资产没有系统标准，容易变成随机装饰。

用户价值

让产品第一眼更可信，学习过程更清楚，行动入口更稳定。

  • 用户能更快判断“现在该做什么”。
  • 深讲内容有更好的阅读层级，不退回长讲义。
  • 状态、错误、加载和完成反馈更一致。
  • 视觉资产帮助理解学习场景，而不是抢注意力。

使用口径

本页是通用规范，不直接代表某个版本排期。

  • 新页面设计前先看本规范。
  • 旧页面改造时优先按本规范收口。
  • 具体实现进入独立版本需求页。
  • 不新增学习功能，不迁移用户数据。

调研结论

成熟设计系统的共同点不是“好看的组件”，而是把原则、token、组件、模式、内容和验收连成一套可执行系统。

Research
参考系统可借鉴点LearnBuddy 转译
USWDS把组件、模式、设计 token、模板、可访问性和性能放在同一个体系里，服务“可访问、移动友好、一致”的公共服务。设计规范不能只写颜色表，要同时定义学习路径、学练单元、自检、登录等页面模式与验收规则。
GOV.UK Design System用 styles、components、patterns 组织规范，并强调复用研究和避免重复劳动。我们应建立“学习场景 patterns”：当前学习、生成进度、复习提醒、展开深讲、错题反馈，而不是堆通用卡片。
IBM Carbon设计系统包含工作代码、设计工具、人机界面指南和社区；原则是开放、包容、模块化、用户优先和一致。LearnBuddy 先轻量落地：CSS tokens + 原生组件规范 + 页面模式；未来再接 Figma 或组件库。
Atlassian Design颜色按语义角色、强调层级和交互状态使用，而不是随手挑色；警告、危险、成功、信息有明确意图。把当前 teal/amber 从“主题色”升级为语义 token：action、learning、review、warning、danger、success、locked。
WCAG 2.2可访问性用可测试标准约束，覆盖感知、可操作、可理解和稳健四个原则。验收必须包含对比度、焦点可见、键盘路径、目标尺寸、文本重排和状态消息，不只靠截图好看。
W3C Design Tokens CGDesign tokens 正在成为跨设计工具和代码共享设计决策的标准方式。从通用规范起用语义 token 命名，避免页面里散落十几套 hex、radius、shadow。
Microsoft HAXAI 体验要覆盖初次交互、交互中、AI 出错时和长期使用，并提供模式和工作簿帮助团队落地。LearnBuddy 的设计规范必须有 AI 状态：能力边界、生成进度、来源可信、错误修复、人工可控和长期记忆。

产品调性

LearnBuddy 的气质不应是花哨的 AI 玩具，也不是冷冰冰的企业后台。

Tone

可信的学习工作台

界面首先要帮用户判断状态、下一步和证据。视觉上克制、清晰、密度适中，接近“学习驾驶舱”而不是营销页。

有温度的 AI 教练

语言和微交互可以温暖，但不拟人过头。鼓励用户行动、复盘和修正，而不是用可爱包装掩盖不确定性。

可验证的内容工厂

来源、质量、生成阶段和返工状态要能被看见。设计要让“认真备课”显性化，而不是让用户误以为只是聊天生成。

规范分层

LearnBuddy 的设计规范按 7 层建设，由产品语义往组件和验收落地。

System Layers
层级规范内容第一版产物
1. 产品原则行动优先、学习工作台感、状态透明、可验证、低噪音。5 条设计原则 + 反例清单。
2. 信息架构页面优先级固定为：当前行动 → 诊断/反馈 → 当前状态 → 解释信息 → 运营信息。登录、学习空间、路径页、学练页、自检页的信息层级图。
3. Design Tokens颜色、字体、间距、圆角、阴影、层级、焦点、状态、动画。web/design-tokens.css 或并入 common.css 的 token 区。
4. 组件规范按钮、标签、卡片、折叠、步骤轨、进度、表单、toast、dialog、空态、加载态。组件使用规则 + 禁用场景。
5. 学习模式生成进度、当前学习、深讲展开、练习反馈、自评、自检、复习提醒、路径锁定。LearnBuddy 专属 patterns。
6. 视觉资产登录背景、路径封面、领域图、概念辅助图、成就图；包含 prompt、尺寸、裁切、回退。Visual Asset System v1。
7. 验收规则截图回归、响应式、对比度、键盘、文本溢出、状态可见、AI 失败路径。浏览器验收清单 + 后续 Playwright 脚本。

适用范围

通用规范的核心是体验基础设施，不是单页改色。

Scope
模块规范要求不做
Design Tokens统一颜色、字体、间距、圆角、阴影、状态色、焦点样式和层级。不继续让页面各自发明主色、圆角和按钮规则。
基础组件建立 button、icon button、tag、card、tabs、dialog、toast、progress、empty、loading、form、status chip 规范。不为了视觉升级引入重型前端框架。
页面优先级首批候选为登录页、学习空间、路径页、学练页、自检页。不一次性重做所有后台和档案页。
信息层级每页第一屏回答“我现在该做什么”，再展示诊断、状态、解释和运营信息。不做营销式 hero，不堆大统计卡和重复 CTA。
可访问性移动端、键盘焦点、对比度、文本溢出和状态反馈进入验收。不靠“看起来还行”收口。

Visual Asset System v1

图片可以用，但必须服务产品语义和学习任务。

Image Rules
场景使用方式验收要求
登录页使用一张大幅背景图建立 LearnBuddy 第一印象，表达安静、专注、个性化学习空间。表单区高对比；移动端可裁切但不得遮挡关键主体；必须有纯色/渐变回退。
学习空间路径卡片可使用领域封面图，帮助快速识别语言、技术、职业、考试等路径。图片降权，主信息仍是路径名称、状态、进度和下一步动作。
学练单元默认优先排版与结构层级；只有图能解释概念、流程、对比或案例时才进入内容卡片。不使用纯装饰大图，不用模糊 stock 风背景。
生成资产每张生成图都必须记录用途、prompt、尺寸、裁切规则和回退方案。不能让随机图片决定产品风格。

设计原则

这组原则用于判断后续视觉方案是否跑偏。

Principles

清楚

每个页面优先呈现当前行动、关键状态和下一步，不把解释信息放到首屏中心。

可信

视觉语言要像学习工作台，克制、稳定、有证据感，而不是活动页或宣传页。

可行动

主按钮、进度、错误、加载、完成和锁定状态必须一眼能判断。

收口结论

设计系统是跨版本规范，具体页面改造再进入版本。

Decision
收口结论：LearnBuddy 设计系统不作为 V0.50 版本需求，而作为长期通用设计规范。后续每个版本只要涉及页面、组件、图片、AI 状态或学习流程展示，都必须对照本规范；如果要大规模改造登录页、学习空间或学练页，再单独立对应版本需求和验收脚本。
