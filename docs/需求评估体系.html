PRD Fitness v0.1

让每个版本在开发前先过一遍需求质量门

这套体系用来回答一个问题：一个版本的需求方案，是否已经足够支撑产品、设计、后端、前端、AI 生成链路和验收一起开工。它不是替代判断，而是把判断标准显性化。

初版体系适用于 V0.46 起每版独立评估

为什么需要

LearnBuddy 的需求不是普通 CRUD。它包含 AI 生成、长任务、来源检索、学习交互、状态恢复和旧数据兼容。如果只写功能点，开发时会反复补洞。

怎么使用

每个版本进入开发前，按 8 个维度评分。平均分达到 3.5 可进入开发，核心维度低于 3 必须先补需求，不直接编码。

输出什么

输出版本评分、缺口清单、开发准入结论、必须补充的测试集和验收口径。后续每次版本评审都复用同一张表。

外部参考与本地化原则

不是照搬某一个框架，而是抽取对 LearnBuddy 有用的质量门。

Sources
参考框架可借鉴点在 LearnBuddy 中转化成什么
用户故事与验收条件需求要说明用户是谁、想完成什么、为什么重要，并落到可验收的条件。每个版本必须有用户场景、核心任务、完成信号和验收样例。
RICE 优先级用 Reach、Impact、Confidence、Effort 约束“为什么先做这个”。版本进入排期前必须说明影响面、价值、信心和工程成本。
ISO/IEC 25010软件质量不只看功能，还看可靠性、可用性、性能、维护性、兼容性等。版本需求必须覆盖状态恢复、旧数据兼容、可维护契约和测试方式。
可用性启发式系统状态可见、贴近用户语言、错误可恢复、减少无关信息。长任务必须有过程状态；学习页必须清楚当前在学什么、下一步做什么。
AI 任务评测AI 功能要有任务特定测试集、评分标准和人类反馈闭环。内容生成不能只看 JSON 成功，要有多领域 golden set、质量报告和返工规则。
本地化取舍：我们不用过重的企业级 PRD 模板；只保留能降低返工的质量门：问题是否真实、边界是否清楚、状态是否完整、数据是否可落库、AI 是否可评测、异常是否可恢复、旧数据是否安全。

8 维需求成熟度评分

每项 0-5 分：0 只有想法，3 可以开发，4 可以测试，5 可以发版。

Quality Gate
维度检查问题3 分标准5 分标准
1. 用户价值解决谁的什么痛点？用户完成后得到什么？有明确用户、场景、目标和成功信号。有真实案例、反例和可量化指标。
2. 范围边界本版做什么、不做什么、依赖什么？范围、非目标、依赖版本写清楚。能防止需求蔓延，并给出后续版本归属。
3. 体验流程用户从进入、等待、完成、失败、回看分别看到什么？有主流程、关键状态和基本错误处理。覆盖移动端、空态、失败、重试、回滚和恢复。
4. 数据契约新增对象、字段、接口、状态机、迁移策略是否清楚？核心实体、状态、读写接口可落地。有 schema、兼容策略、迁移 dry-run 和回滚方案。
5. AI Loop 质量AI 输入、来源、生成、评估、返工、停止条件是否完整？有生成流程、质量门和失败降级。有多轮 critic/revise、来源置信度、预算、trace 和可复盘报告。
6. 验收测试如何证明做对了？靠人工看还是有评测集？有端到端验收场景和基础测试。有 golden set、异常集、旧数据集、浏览器截图和自动回归。
7. 运营可观测上线后怎么知道卡住、质量差、用户不懂？有事件、日志、状态页或后台指标。有日报、聚类、告警、慢任务定位和用户痛点分析。
8. 发版安全会不会影响线上用户数据？能否灰度、回滚、降级？说明数据安全和基本回退。有灰度策略、权限边界、积分影响、回滚脚本和监控阈值。

V0.46 / V0.47 初步评估

结论：两版都比早期方案可开发，但开发准入程度不同。

Assessment
版本平均分结论当前可做不建议直接做
V0.46 教学内容 Loop v13.7 / 5可进入开发准备，但需要先补评测集和接口级细节。M1 数据契约、fixtures、LessonBuildGraph skeleton、学习页状态原型。不要直接一次性开发完整生成系统；先把质量门和回归样例建起来。
V0.47 路径级 Loop v13.3 / 5仍是候选方案，方向清楚，但依赖 V0.46 的真实数据和运行时。可以做状态机设计、事件模型、JobReconciler 方案和接口草图。不要现在做完整路径级自适应；没有单节质量数据，路径优化会空转。

开发前必须补的缺口

不是把需求写得更长，而是补上会影响开发收敛的关键件。

Gaps

V0.46 必补

  • 建立 20-30 条内容质量 golden set：技术、语言、写作、营养、考试、职业转型各覆盖。
  • 给 QualityReport 写明确阈值：depth、source、interactivity、clarity、risk。
  • 补接口草图：创建生成任务、查询状态、读取 lesson、保存学习输入、重生成。
  • 补旧数据兼容样例：旧 explain/practice/produce 到 LessonFlow 的转换 fixtures。
  • 补学习页关键状态图：加载、生成中、失败、已完成、回看、重生成。

V0.47 必补

  • 先等 V0.46 产出真实 QualityReport 和用户学习事件，再锁定路径调参策略。
  • 补 PathLoopState 状态机图，明确 current_unit、unlocked、pending_job、completed 的关系。
  • 补任务一致性策略：任务已完成但前端仍等待、缓存已存在、重复点击完成、超时重试。
  • 补 PathEvent 事件去重和幂等规则，避免重复扣积分和重复生成。
  • 补后台分析的最小指标，不要一开始做大而全 BI。

建议的开发准入规则

以后每个版本进入编码前都按这个规则判定。

Gate
阶段分数区间允许动作禁止动作
方向想法0-2.4讨论、调研、竞品分析。不进入开发排期。
方案草案2.5-3.4做技术 spike、数据建模、原型验证。不做完整功能发版。
开发准备3.5-4.1可排 M1/M2，先做契约、fixtures、接口 skeleton。不省略测试集和兼容策略。
发版候选4.2-5.0进入完整实现、端到端验收、灰度和部署。不无监控上线。
