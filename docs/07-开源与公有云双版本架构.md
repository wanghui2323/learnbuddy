# LearnBuddy 开源与公有云双版本架构

> 状态：2026-09-02 已确认，作为本轮开源改造的产品与技术真相源。
>
> 这份方案替代“由 LearnBuddy 官方为所有 2C 用户共享托管 OpenClaw”的产品方向。历史 PoC 代码可以保留兼容，但不能作为公有云默认能力继续扩张。

## 1. 一句话决策

LearnBuddy 使用一套学习引擎、两种发行模式：

- **Cloud 公有云体验版**：让用户快速看懂并体验核心学习闭环，平台承担有限模型额度，不接用户的飞书或 OpenClaw。
- **Personal 个人开源版**：每个用户部署自己的 LearnBuddy，自备模型 Key，并可选接入自己部署的 OpenClaw 与自己的飞书应用。

两种模式共享计划、任务、进度、掌握度、记忆和提醒规则；差异统一由后端 `RuntimeCapabilities` 决定，前端只按能力呈现，不能靠隐藏按钮代替权限控制。

## 2. 产品架构

| 能力 | Cloud 公有云体验版 | Personal 个人开源版 |
|---|---|---|
| 目标 | 低门槛体验与理解产品 | 成为用户长期拥有的个人学习伙伴 |
| 账号 | 开放注册，多用户隔离 | 首次初始化唯一 owner，之后关闭注册 |
| 模型凭据 | 平台统一持有 | 用户在自己的部署环境中 BYOK |
| 使用限制 | 积分/token 配额、速率限制 | 不设平台配额，仅受用户模型账户限制 |
| 学习数据 | 平台按用户隔离，支持导出/删除 | 保存在用户自己的数据卷中，支持备份/恢复 |
| Web 学习闭环 | 支持，但体验额度有限 | 完整支持 |
| 飞书 / OpenClaw | 不开放，不收集用户 App Secret | 可选；凭据只保存在用户自己的环境 |
| 管理后台 | 平台运营者可用 | 不提供多用户运营后台 |
| 积分卡 | 可用 | 不出现 |
| 付费订阅 | 本周不做 | 不需要 |

公有云不是“阉割版页面”，而是一条完整但有限的体验链：

```text
注册 → 描述学习目标 → 简化摸底 → 生成体验路径
     → 完成一节课 → 看到初步画像 → 查看剩余额度
     → 导出数据 / 前往 GitHub / 部署个人版
```

个人版是一条长期拥有链：

```text
部署 → 创建唯一 owner → 配置模型 Key → 创建学习路径
     → 可选启用 OpenClaw → 连接自己的飞书 App
     → 对话调计划 / 记学习事实 / 收到提醒 → 备份与升级
```

## 3. 技术架构

```text
                         LearnBuddy 单一代码仓库
                                   │
                      RuntimeCapabilities（后端真相源）
                         ┌─────────┴─────────┐
                         │                   │
                  edition=cloud       edition=personal
                         │                   │
              ┌──────────┴────────┐    ┌─────┴──────────────┐
              │ FastAPI + Web     │    │ FastAPI + Web      │
              │ 多用户认证/配额   │    │ 单 owner / BYOK    │
              │ SQLite/数据目录   │    │ 私有数据卷         │
              └──────────┬────────┘    └─────┬──────────────┘
                         │                   │ MCP（受限工具）
                    平台 LLM API             ▼
                                      用户自有 OpenClaw（可选）
                                               │
                                      用户自有飞书应用机器人
```

职责必须保持单一：

| 组件 | 唯一职责 |
|---|---|
| LearnBuddy Core | 学习计划、任务、进度、掌握度、画像、记忆、提醒定义的唯一真相源 |
| LearnBuddy API/MCP | 提供带身份注入、归属检查和审计的有限学习工具 |
| OpenClaw | Agent 循环、会话编排和飞书对话通道，不保存第二套学习计划 |
| 飞书应用 | 用户的对话入口；App ID/Secret 归用户，不上传公有云 |
| LLM Provider | Cloud 由平台统一调用；Personal 由用户自备 Key |

## 4. RuntimeCapabilities 合同

唯一模式开关：

```bash
LEARNBUDDY_EDITION=cloud     # 公有云默认兼容模式
LEARNBUDDY_EDITION=personal  # 个人部署模式
```

前端通过公开只读接口读取后端策略。建议返回结构：

```json
{
  "edition": "personal",
  "registration": "setup_only",
  "quota_mode": "provider",
  "llm_credentials": "owner_managed",
  "feishu": true,
  "openclaw": true,
  "backup_restore": true,
  "admin_console": false
}
```

约束：

1. 环境值非法时启动失败，不能静默回退成另一个版本。
2. 后端先守卫注册、积分、后台和集成接口；前端隐藏仅用于减少认知噪音。
3. `personal` 首次只能创建一个 owner；初始化完成后注册接口必须拒绝第二个账号。
4. 不删除现有 `users` / `user_id`。个人版仍以固定 owner 身份运行，避免破坏现有数据归属和工具守卫。
5. 旧的共享 OpenClaw 绑定接口只作为迁移兼容代码存在；Cloud 不暴露，Personal 默认走本地 MCP/私网接口。

## 5. OpenClaw 与飞书边界

OpenClaw 的 Gateway 是一个信任边界。公开 2C 用户不能共享同一个 Gateway 来获得真正的租户安全隔离，因此本方案不在公有云托管共享 OpenClaw。

个人版默认提供三档：

1. **Web only**：只启动 LearnBuddy，资源最少。
2. **Web + OpenClaw**：OpenClaw 调用 LearnBuddy MCP，用于对话和自动化。
3. **Web + OpenClaw + 飞书**：用户用自己的飞书自建应用，通过 WebSocket 长连接接入，无需给 Gateway 暴露公网回调地址。

第一版不实现 LearnBuddy 原生飞书入站 Agent。飞书对话统一由 OpenClaw 承担，避免同时维护两套 Agent 循环。

默认安全策略：

- Gateway 只监听本机或私网，不直接暴露公网。
- 只允许 owner 的飞书 `open_id`；群聊默认禁用。
- 只开放 LearnBuddy MCP 白名单工具。
- 默认禁用系统命令、浏览器、任意文件写入和 elevated 权限。
- 模型 Key 与飞书 App Secret 只进入用户自己的 `.env`/Secret，不写数据库、不进入日志。
- 提醒的时间、状态和发送事实仍由 LearnBuddy 保存；首个开源版本由 LearnBuddy 的确定性 scheduler 直接向飞书发送提醒，OpenClaw 不再轮询同一队列，避免重复投递。

## 6. 公有云最小 SaaS 范围

本周保留且必须由后端执行：

- 注册、登录和会话管理。
- 用户级数据隔离、导出与删除。
- 积分/token 配额和接口限频。
- 管理员查看用量、质量和异常。
- 明确的额度状态、用尽状态与私有部署引导。
- 基础健康检查、日志和备份。

本周不做：

- 支付、订阅、套餐和发票。
- 团队/组织/企业 SSO。
- 公有云上的用户飞书密钥托管。
- 为每个用户创建或托管 OpenClaw。
- 任意 Agent 工具和系统权限。

## 7. 状态与闭环

### Personal 初始化

```text
setup_required ──创建 owner──> ready
      │                           │
      └──任何学习 API：拒绝       └──再次注册：拒绝
```

### Agent 连接

```text
disabled → configured → verified → active
                 │          │         │
                 └─凭据错误─┴─运行异常┴→ degraded（可诊断、可重试）
```

“保存了 App ID/Secret”不等于“飞书已连通”；只有真实消息往返和学习数据回写成功，才能标记 `active`。

### 提醒

```text
规则保存 → 到期生成 delivery → 唯一投递者领取 → 飞书发送
       → sent / failed（有界重试）/ skipped（暂停、静默或未连接）
```

## 8. 本周发布门槛

### P0：个人版可拥有

- 在干净的 macOS 或 1C2G Linux 环境，非作者用户 30 分钟内完成启动。
- 首次创建唯一 owner；重启后账号、路径和学习进度仍在。
- 用户用自己的模型 Key 创建路径并完成一节学习。
- 可选 OpenClaw 能读取今日计划、调整提醒并写回同一份学习数据。
- 用户自己的飞书能私聊机器人；非 owner sender 被拒绝。
- 错误模型 Key、错误飞书凭据和 OpenClaw 未启动都有可理解的诊断。
- 数据可以备份，并在新数据卷中恢复后重新打开。

### P0：Cloud 可体验

- 新用户可注册并完成一条有限体验链。
- 每个用户只能访问自己的学习数据。
- 配额用尽后后端拒绝继续消耗，并给出私有部署出口。
- Cloud 的页面和 API 都不暴露飞书/OpenClaw配置能力。
- 管理端可以观察用户量、模型消耗和失败。

## 9. 迁移顺序

1. 建立 `RuntimeCapabilities` 与后端守卫，保持 `cloud` 为兼容默认值。
2. 补齐 `personal` 首次 owner 初始化和无积分运行。
3. 让前端入口、额度和集成区按能力呈现。
4. 提供 Docker/Compose、持久卷、健康检查和个人部署说明。
5. 将 OpenClaw 作为可选独立容器接入，固定版本并限制工具。
6. 在干净机器完成 Web、重启持久化、OpenClaw、飞书、备份恢复验收。
7. 完成开源发布信息后再打首个公开 tag。

## 10. 发布前仍需产品所有者提供

- 公开 GitHub 仓库的组织/账号和最终仓库地址。
- MIT License 的版权主体与年份。
- 公有云正式域名、体验额度和全局预算上限。
- 一组仅用于真实验收的模型 Key；Key 不进入仓库。
- 一套个人飞书自建应用用于端到端验收；App ID/Secret 不进入仓库。
