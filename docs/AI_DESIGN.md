# LearnBuddy · AI Design 执行规范

> 2026-09-06 · 规范 v1，跨版本使用。是新改页面的设计合同，不代表现有页面已经全部迁移。图形示例见 [学习地图](./学习地图.html#design)，背景原则见 [设计规范](./设计规范.html)。

## 1. 先交付页面合同，再生成界面

设计输入必须包含：对应 PRD ID、使用者、核心任务、读写对象、主行动、成功结果、加载/空态/失败/恢复、手机端优先级。缺任意关键项时先澄清，不能靠 AI 自行补一个“漂亮首页”。

示例：学习空间服务“决定今天学什么”；主行动是进入当前任务；次行动是查看路径或切换任务；学习记录是事实，推荐只是建议。完成率和掌握度不能共用含糊的百分比。表单保存不算学习完成。

## 2. 视觉语言与 Tokens

目标是安静、温暖、可信的学习工具。以内容、任务和证据建立层级，不做大面积营销 Hero，不靠卡片套卡片制造复杂感。

以下为现有 web/assets/style.css 中可复用的值；web/index.html 等仍用别名和局部定义。修改页面前核对其实际加载样式，不可宣称已存在统一的全站组件包。

| 用途 | 现有变量 | 值 | 约束 |
|---|---|---|---|
| 主行动 / 选中 | --primary | #2C6E6A | 同一区域只突出一个主行动 |
| 主行动悬停 | --primary-hover | #235955 | 颜色变化不替代键盘焦点 |
| 提示 / 待处理 | --warning | #D98A3D | 用图标和文字补足语义，避免小号橙字放白底 |
| 错误 / 危险 | --danger | #C2603F | 错误说明同时给恢复操作；删除与普通操作分组 |
| 正文 / 次级正文 | --text / --text-soft | #2B2926 / #6B6760 | 关键状态不使用低对比的 --text-muted |
| 页面 / 内容底 | --bg / --bg-card | #F7F4EE / #FFFFFF | 背景降权，避免大色块抢任务注意力 |
| 间距 | --space-1 至 --space-12 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 px | 优先用已有尺度，新增要解释用途 |
| 圆角 | --radius / --radius-lg | 8 / 12 px | 操作控件 8，内容容器 12；不要全部胶囊化 |

新增页面排版基线：系统中文字体优先，正文 16–18px、行高 1.65–1.8；主标题 28–36px、章节 20–24px、辅助文字不小于 13px。学习正文保持舒适行长；移动端边距至少 16px。以上尺寸是本规范目标，不是对每个历史页面的测量结果。

## 3. 布局与信息层级

- 学习空间：当前任务和继续入口在前，路径列表在后，积分和账号不抢学习主线。
- 路径页：目标、周期与阶段位置先于长内容；解释为什么补强某能力，再给具体安排。
- 学练页：当前问题 → 讲解 / 例子 → 用户行动 → 反馈与下一步。不要把几千字一次性塞入不可扫描的卡片。
- 诊断页：分开独立能力、AI 协作能力和自信；依据可查看，不确定性可见。
- 桌面信息可以并列；390px 单列按任务优先级重排，不能直接缩小桌面截图当移动端设计。

## 4. 组件与状态合同

| 组件 / 场景 | 默认 / 运行中 | 成功 | 失败与恢复 |
|---|---|---|---|
| 主按钮 | 明确动词；提交期间原生 disabled 或等效可访问守卫 | 指向实际结果，不只 Toast | 恢复可操作并显示原因，保留表单内容 |
| 表单 | 标签常驻；校验靠近字段 | 服务端返回后确认保存 | 错误与字段关联，不清空用户输入 |
| 长任务 | 显示真实阶段；未知耗时不编百分比 | 结果可打开，状态可重读 | 给重试/继续入口；说明是否保留进度 |
| 评估结果 | 未评估与低置信明确区别 | 展示证据与来源 | 不把判分失败写成能力为零 |
| 提醒设置 | 时间、时区、开关显示当前值 | 保存后重读校验 | 失败不显示“已安排”；渠道未配单独说明 |
| 空态 | 解释为何没有内容 | 一个清楚的下一步 | 不用随机假数据填满页面 |
| 删除操作 | 明示对象和影响；二次确认 | 完成后列表/详情一致 | 取消不写入；失败保留原内容 |

状态不能仅靠颜色。键盘操作可达、焦点可见，弹窗关闭后焦点返回触发点；关键反馈不能只在几秒消失的 Toast 中出现。触控目标按 44px 左右设计，紧凑桌面控件也需足够点击区。这是项目约束，不声称已有第三方可访问性认证。

## 5. AI 交互的特殊规则

1. **生成和保存分开**：流式文本结束不等于服务端持久化完成；只有写入成功才能提示保存。
2. **推断和事实分开**：推荐、估计与已保存记录使用不同措辞；不得把模型分数写成经过校准的概率。
3. **过程透明但不泄露隐私**：呈现阶段、来源和判断依据，不要求暴露隐藏推理或原始敏感日志。
4. **可纠正**：允许用户指出评估异议、修改约束；入口应靠近结果，不藏到设置深处。
5. **渠道一致**：网页与 Agent 修改同一领域对象；Agent 只按工具返回说成功，工具不可用就说明未完成。
6. **可恢复**：刷新、超时、重启后恢复必须由真实任务/评估状态支撑，不能只保存在当前页面内存里。

## 6. 可直接交给 AI 的任务模板

```text
先读 SPEC 的当前 ADR、docs/01-需求方案.md 当前合同与 docs/AI_DESIGN.md。
本次需求 ID：……；只修改页面：……；不要改动：……。
使用者 / 核心任务：……；读写的对象与接口：……。
先提交：页面信息顺序、唯一主行动、状态矩阵、复用的 Token 和组件。
实现时沿用现有原生前端；不生成假的统计、成功态或不可工作的按钮。
无法确认的后端能力显式标注，不自行模拟。
完成后给出桌面与 390px 的真实页面证据，以及保存后刷新、失败重试、权限反例。
分别报告规范满足项、现有差距、尚未验证项。没有证据，不宣称全站统一或上线。
```

## 7. Design QA 与交付物

每次页面改动交付四件：页面合同、状态矩阵、实现代码、截图和交互证据。复核 390 / 768 / 1440px；检查文字截断、横向溢出、图片裁切、焦点、禁用、加载、失败与恢复。截图有视觉价值，但不能代替一次真实用户动作。

本轮仅新增规范与可视化样例，未对业务页面做整站迁移；已有公共样式是复用起点，不是完整设计系统完成证明。
