① 用户要的不是一份计划，而是能继续的学习

③ 页面只是入口，后端对学习事实负责

从一句话到可确认的副作用

④ Agent 改的是学习状态，不是另写一份口头计划

“暂停我的学习提醒”是一个受控写操作。对话需要识别本人、读取当前规则，再调用工具保存；成功回复应以工具结果为依据。身份来自可信渠道信息，不能由模型随意填写 user_id。

⑤ 开发工作台：需求、实现与验收的连接处

学习空间面向学习者；开发工作台面向维护者和学习项目构建的人。它用版本号连接任务、依赖、负责模块、退出门和证据。工作台是人工维护的静态 HTML，不是已经接通 GitHub 的实时任务系统。

反馈 / 想法 → 需求判断 → 版本范围 → 任务依赖 → 实现 → 验收 → 下一版

打开 V0.53 任务树，追踪“能力画像必须可追溯”这一个需求：数据模型先保存身份与答案，判分产生证据，结果页呈现依据，生成器消费画像，最后由 Eval 与发布门验证。任务的顺序来自数据依赖。

打开开发工作台过程入口V0.53 完整任务树ADR 决策记录发布门脚本需求评估体系

复用方法：给你自己的一个小需求建立版本卡，至少连接“为什么做、依赖什么、改哪里、如何验收”。状态只有在对应证据成立后才改变。不要将不同版本的历史测试数相加，当作本周成果。
