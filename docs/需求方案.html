产品定位

LearnBuddy 不是课程平台，也不是普通聊天机器人，而是把“目标澄清、即时评估、个性化路径、持续执行、记忆回流”做成可复用的学习系统。
元目标

把作者 dogfood 过的方法论抽象成面向所有人的平台。

不限领域

语言、编程、写作、营养、考研、职业转型都进入同一引擎。

用户得到什么

不是一份模板计划，而是一套可执行、可考核、可调整的学习闭环。

首个 demo

日语 N3 备考 3 个月，用非技术场景验证通用性。

需求架构图

需求层次要从下往上看：先有基础学习闭环，再有长期陪伴，再接商业化底座，最后才是升级模式。
理解顺序要固定：先把基础学习系统做扎实，再叠加升级模式，最后通过账号与商业化底座支撑正式运营。

用户旅程闭环图

用户不会只生成一次路径就结束，而是持续进入“执行 → 评估 → 调整”的循环。
阶段用户感知系统职责
进入像教练在收集你的真实情况把自然语言收敛成结构化参数包
评估知道自己真实起点，而不是只写一句 baseline形成画像和差异化判断依据
生成拿到属于自己的学习路径输出可执行、可考核、可调整的计划
执行每天都知道该学什么、练什么、复习什么推荐、学练、学情、提醒联动
调整系统越用越懂自己记忆、掌握度和重规划持续回流

用户模式分层

产品不是一种模式走天下，而是默认模式 + 用户自选升级模式的组合。
模式定位核心能力收费
标准学习模式默认模式路径生成、学习空间、学练、学情、推荐、复习、基础提醒免费或基础订阅
个人助理模式升级模式托管的专属学习助理、长期记忆、主动提醒、主动复盘、跨端联动、IM 对话入口额外收费，用户自选开通
OpenClaw 只承担升级模式的运行时和承载层，不替代 LearnBuddy 主系统，也不让学习真相源跑到外部去。

评估闭环细则

即时基线评估必须有可解释的出题范围和判分标准，独立和协作出题分开跑，避免“会不会”被 LLM 表现掩盖。
维度独立评估协作评估画像产出
出题范围用户目标领域的核心概念、关键操作、典型陷阱同一范围，但允许使用 AI 辅助领域覆盖矩阵
题量与时长6–10 题，控制在 8–12 分钟4–6 题，控制在 10–15 分钟完成度与耗时

怎么看接下来几周是否 OK

如果你要用这页判断排期和节奏，重点看这 4 件事是不是一起推进，而不是只盯一个点。
第一类

学习闭环有没有继续变完整：评估、自检、复习、重规划有没有贯通。

第二类

长期连续性有没有增强：后续周、推送回流、个人记忆有没有继续往前走。

第三类

运营底座有没有定清楚：登录、支付、积分、升级模式有没有成链。

第四类

有没有守住边界：不把主系统真相源、Agent、IM、支付混到一起。

边界与非目标

把不做什么说清楚，后续排期才不会失焦。
主题当前边界
主产品边界继续以 LearnBuddy Web / PWA 为主，不因为 OpenClaw 就推翻主产品结构。
学习真相源计划、学情、记忆、推荐、权益都统一在 LearnBuddy 主系统，不在 IM 侧分叉。
商业化边界对外卖的是订阅、积分和升级模式，不直接暴露 token 或模型成本。
移动端边界当前不做独立 App，不在手机端重做完整学习流程。
Agent 边界先把学习闭环做好，再把 agent 接到上层；不允许“什么都上 agent”。
