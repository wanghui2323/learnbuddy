## 1. 现在谁负责什么

从本次文档收口开始：

- `03-开发方案与计划.md` 负责当前需求、技术、进度、计划
- `开发方案与计划.html` 负责主方案的 HTML 直接查看
- `工作台.html` 负责 HTML 总览展示
- 本文只负责 **协作规则、DoD、更新流程**

也就是说，本文**不再单独维护一套项目现状与路线图**。

## 2. 看板规则

任务在 5 个状态间流转：

```text
Backlog ──→ Todo ──→ Doing ──→ Review ──→ Done
（待规划）  （已排期）（进行中）（待验证）（已验收）
```

| 状态 | 含义 | 进入条件 |
|---|---|---|
| **Backlog** | 已识别，未排期 | 写清描述即可 |
| **Todo** | 已排进某里程碑 | 关联验收标准 |
| **Doing** | 正在做 | 同一时间高层任务尽量不超过 1-2 个 |
| **Review** | 已开发完成，待验证 | 自带验证产物 |
| **Done** | 已验收 | 满足 DoD |

> 铁律：同一会话只做一个高层任务，避免 kitchen-sink session。

---

## 3. 任务完成定义（DoD）

一个任务标记 `Done` 必须满足：

- 代码或文档改动已实现目标
- `core/` 改动时 `pytest` 通过
- `web/server` 改动时做浏览器或接口实测
- LLM 相关变更有“看得到的回退路径”
- 改动较大前先提交当前状态
- commit message 使用中文 Conventional Commits
- 涉及重大决策时，写入 `SPEC.md` ADR
- 每轮开发结束后更新 `03-开发方案与计划.md` 和 `工作台.html`

---

## 4. 更新流程

每轮开发结束后按这个顺序更新文档：

1. 更新 `03-开发方案与计划.md`
2. 同步 `工作台.html`
3. 如涉及重大决策，更新 `SPEC.md` ADR
4. 如只改协作规则，再更新本文

---

## 5. 风险与失败模式

### 5.1 常见风险

| 风险 | 处置原则 |
|---|---|
| 范围蔓延 | 优先回到 `03` 主文档确认当前阶段任务 |
| 文档漂移 | 发现冲突时，以 `03` 主文档为准 |
| 看似正确但没验证 | 不合并，先补验证 |
| 同一问题连续两次改错 | 停下，收敛问题后再继续 |

### 5.2 立刻 STOP 的 5 种情况

| 失败模式 | 处置 |
|---|---|
| Kitchen-sink session | `/clear` 后重起 |
| 反复纠错 | 写更具体 prompt 后再做 |
| Trust-then-verify gap | 先补验证 |
| 无限探索 | 先收敛 scope |
| 未经确认的文档分叉 | 回到主文档统一口径 |

## 6. 工作台更新说明

`docs/工作台.html` 是单文件离线总览页，适合快速查看。

更新方式：

- 直接修改 HTML 内嵌的 `DATA` 对象
- 内容必须与 `03-开发方案与计划.md` 保持一致
- 如果两边不一致，以主文档为准，工作台随后补齐
