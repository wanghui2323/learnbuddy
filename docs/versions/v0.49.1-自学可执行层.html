已验收 · V0.49 之后的体验质量补丁 · ADR-048

让 90 分钟课程从“内容更厚”变成“学习者能独立完成”

V0.49 的工程质量 loop 已经跑通，真实 DeepSeek golden case 也通过了密度、展开层和时长合同。但从学习者视角看，课程仍像一份加厚讲义：个性化信号有时像标签堆叠，练习缺少模板、参考答案和高阶产出，90 分钟学习计划还不够可执行。V0.49.1 不重开大架构，而是把下一轮 loop 聚焦在自学可执行层：语言像个人学习任务，产出有模板，练习有参考答案，验收能判断用户是否真的学会。

状态：真实 LLM 验收通过目标：自学可执行耗时：183.82s

需求方案

用户选择每天 1-2 小时，不应该拿到一份只能看 20 分钟的提纲，也不应该只看到“读一读、复述一下”。

  • 学习者打开页面后能知道接下来 90 分钟每一步做什么。
  • 核心任务必须有模板、示例、参考答案或评分标准。
  • 练习要能暴露理解错误，而不是只做选择题或短复述。
  • 个性化要自然落在任务难度、检查点和反馈标准里。

技术方案

沿用 V0.49 的受控流水线和 bounded quality loop，只新增自学可执行性约束。

  • prompt 禁止课堂话术和原始学员标签堆叠。
  • 质量门新增模板、参考答案、高阶练习和自学语言检查。
  • critic 新增 self_study_fit、artifact_completeness、assessment_authenticity。
  • 真实样本继续走后台任务，300 秒硬预算内验收。

开发范式

这是一轮工程 loop，不是一次拍脑袋改 prompt。实际推进中先暴露真实失败，再加确定性兜底，最终第三轮线上样本过关。

  • 首轮真实 LLM 因自学产物不足失败，证明质量门有效。
  • 第二轮加入长课自学合同兜底后通过，但 critic 仍指出样例不够直接。
  • 第三轮强化“已填写参考答案”后通过，并且 critic 无阻断项。
  • V0.49.1 收口后进入部署前回归和线上重生成对比。

Loop 目标

这轮不是追求更长，而是让学习者能开始、推进、产出、检查。

Loop Goal
指标问题表现V0.49.1 目标
知识完备性内容有机制和边界，但缺少可迁移的完整知识框架。核心卡必须给出概念关系、判断流程、边界条件和常见误区。
学习质量用户看完知道“是什么”，但不一定能做出一个可检查产物。每节 60 分钟以上课程必须有模板化产出和参考答案。
需求匹配度90 分钟合同存在，但活动计划仍可能像短课拉长。activity_plan 必须把时间分配到读、做、改、验收，而不是泛泛列步骤。
个性化构建学员信号容易以“已具备/薄弱点”标签形式出现。个性化必须自然进入任务难度、提示粒度、验收标准和错误预警。
自学可执行性像老师讲课材料，不像一个人独立学习的工作单。禁止课堂话术；页面能直接指导一个人完成学习和产出。

开发 Loop

每一轮都用同一套节奏推进，避免无限发散。

Engineering Loop
阶段做什么输出物停止信号
1. 观察用当前线上模型生成 90 分钟 golden lesson，记录耗时、质量分、人工阅读问题。样本 JSON、预览 HTML、人工审计结论。问题能归因到自学执行层，而不是泛泛说“不够好”。
2. 设假设只选择 1-2 个可验证改动，例如“增加参考答案会提升产出可执行性”。SPEC ADR / 版本任务页更新。假设能被测试或真实样本验证。
3. 实现改 prompt、质量门、critic 或渲染，保持旧 schema 兼容。代码与测试。单测通过，旧 lesson 不破。
4. 真测用线上接入的 LLM 重新跑同一类课程，统计 wall time 和 loop 轮数。质量报告、耗时、预览页。300 秒硬预算内完成或转后台可恢复。
5. 人读从学习者视角判断能否独立完成 60-90 分钟学习。通过/不通过 + 具体下一轮改动。连续一轮无明确可迭代项，或达到验收门。

验收门

只有真实样本和人工阅读都过，才算 V0.49.1 收口。

Acceptance Gate

时间受控首请求超时后能转后台；后台硬预算默认 300 秒，不能前端一直等待到报错。

人工学习视角打开最终预览页后，学习者不需要老师解释，也能知道 60-90 分钟如何完成、如何检查、如何改进。

停止条件

Loop 必须有结束，而不是一直“再优化一下”。

Stop Rule
停止结论：第三轮真实 LLM 样本满足验收门，耗时低于 300 秒硬预算，质量门、critic 和人工阅读都不再出现学习阻断项，V0.49.1 收口。后续若继续提升，应进入新版本，不在本补丁里无限扩张。
