把单节出课从巨型 prompt 改成受控内容生产线

V0.48 解决的不是“prompt 再写强一点”，而是修复生成架构：先过滤低质来源，再单独做课设，再围绕锁定主线写课，最后用 critic 检查内容是否具体、有洞见、讲透边界和诚实接地。

状态：待真测提交：7a8ca34上线前：真 LLM E2E

需求方案

用户反馈“内容看着完整但学不到东西”，根因是生成链路优化错了目标。

  • 不能再让单模型一次性吐完整 lesson 巨型 JSON。
  • 不能只靠卡片数量、字数和关键词判断质量。
  • 不能把低质 SEO 摘要当事实 grounding 注入模型。
  • 每节课必须有一个换主题就不成立的具体洞见。
  • 上线前必须用真实重新生成结果验证锐度。

技术方案

受控 workflow，单模型多阶段，不做自由多智能体。

  • design_lesson：reasoner 只做课设、angle、anti_generic。
  • write_lesson：chat 围绕课设写深内容。
  • critic_lesson：reasoner 按 specificity / insight / depth / grounding 锐评。
  • revise_lesson：chat 根据具体指令定向修订一次。
  • select_quality_sources + 正文抓取先修 grounding。

开发范式

保留旧 schema 和回退路径，先让新链路可观测。

  • 旧 lesson.md 单段式继续作为 fallback。
  • pipeline / reasoner / review / 来源阈值都可用 env 降级。
  • 新增 _critic、_critic_revised、_pipeline 观察字段。
  • 服务端进度展示拆成 source_fetch / design / write / critic / revise。
  • 部署前先人工读新旧内容，不只看 JSON 是否完整。

根因到方案映射

每个架构问题都必须对应一个工程动作，避免再次变成 prompt 装修。

Problem Matrix
确认根因工程修复验收信号
一次性输出巨型 JSON，注意力被 design / explain / cards / lab / practice / citations 摊薄。拆成 design_lesson 和 write_lesson，写课只能围绕锁定课设推进。新 lesson 的 design.angle 和主线能解释这一节为什么不能套到别的主题。
质量门奖励结构完整，不奖励教学洞见。新增 critic_lesson，按 specificity、insight、depth、grounding 给分并输出重写指令。_critic.scores 能指出“太通用 / 没讲透边界 / 来源不诚实”等具体问题。
低质量来源摘要被直接喂给模型，噪声污染备课。select_quality_sources 按 authority / relevance 过滤，优质来源抓正文；全被过滤时 context 留空。低质 web 来源不进入 prompt；_source_pack.grounding 能说明 grounded / ungrounded。
内容对学员信号不敏感，像通用讲义。服务端把 concept_mastery 和 memory.recall 压成 learner_signals 注入课设。课设阶段 prompt 能看到薄弱点、已掌握点和偏好；内容难度随信号变化。
多段调用成本和失败率上升。保留旧单段 fallback；ITUTOR_LESSON_PIPELINE / ITUTOR_LESSON_REASONER 可降级。reasoner 失败或关闭时仍能返回可展示 lesson，不影响旧缓存读取。

V0.48 是受控流水线，不是自由多智能体。

Workflow

修订deepseek-chat草稿 + critic 指令。修订后的完整 lesson。失败保留草稿与 critic 记录。

开关与兼容

质量优先，但必须能控成本、控风险、可回退。

Controls
开关默认作用什么时候用

ITUTOR_LESSON_REASONER1课设和 critic 优先用 reasoner。需要省钱或 reasoner 不稳定时改用 chat。

DEEPSEEK_REASONER_MODELdeepseek-reasoner指定推理模型。供应商模型名变化时只改 env。
