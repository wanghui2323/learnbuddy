让核心内容既能讲深，也能支撑真实学习时长

V0.49 不是推翻 V0.48 流水线，而是补上它暴露出的质量缺口：先让短句清单式 lesson 不能过关，再引入 expansions[] 展开层，把机制、边界、反例、来源证据和 worked example 放到卡内按需展开；同时复用 onboarding 已收集的每日学习时长生成 _session_contract，让 1–2 小时学习者拿到完整学习单元，而不是 20–40 分钟微课；critic 触发后进入有边界的质量迭代 loop，直到通过、停滞、变差或达到轮数上限。

状态：golden case 通过ADR-046下一步：人工读课 + 部署前回归

需求方案

用户实测反馈：新流水线生成的内容仍明显偏少，深度不够；如果用户选择每天 1–2 小时，单节内容必须能支撑这个学习时长。

  • 不能把 6 张短卡、一个图解和两个例子当成“深度课”。
  • 核心卡必须能独立教学，而不是只列本节怎么学。
  • 更多信息要按需展开，不直接挤满首屏。
  • 目标是知识完备性、学习质量、需求匹配度和个性化学习构建一起达标。

技术方案

把“核心教学密度 + 可展开信息层 + 学习时长合同”纳入 prompt、critic、本地质量门和学习页渲染。

  • lesson_write.md 要求至少 3 张深讲卡。
  • content_quality.py 检查 teaching_chars、dense_teaching_cards、estimated_minutes 与 activity_plan。
  • 新增增量字段 expansions[]、activity_plan、rubric。
  • 学习页默认展示核心卡，并展示“本节学习安排”。

开发范式

兼容旧 lesson schema，增量支持展开层，并把展开层纳入质量门和 bounded loop。

  • 旧缓存继续可读，不迁移线上数据。
  • 缺 expansions 时照常展示 body/items。
  • 质量门新增 expansion_blocks 与 expansion_kinds。
  • ITUTOR_LESSON_MAX_REVISIONS 默认 3、最高 5，候选变差则保留 best。
  • 部署前必须人工读一节真 LLM 重生成内容。

Decision
收口结论：V0.48 的流水线方向是对的，但质量门仍太容易被短句卡片刷过。V0.49 以后，生成链路必须证明自己写出了足够的核心教学内容，并且能支撑用户实际选择的学习时长；更多信息不直接堆在首屏，而是通过 expansions[] 展开层承载；修订不再只做一次，而是在 bounded loop 中按四个质量指标保留最佳版本。本轮真实线上验收已通过：scripts/verify_lesson_quality_loop.py 跑 90 分钟 Agent memory golden case，180.00s 完成，critic 分数最低 80。
