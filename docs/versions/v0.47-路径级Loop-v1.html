让整条学习路径随着学习行为持续优化

V0.47 要解决的不是“再生成更多内容”，而是先让路径运行机制可信：用户学到哪里就从哪里继续，完成一天后下一天能提前准备，异常状态能被发现和恢复。后台质量分析和自适应重规划保留到后续版本。

状态：已开发提交：807323b回归：259 passed

需求方案

把学习路径从静态计划升级为“可继续、可恢复、可解释”的运行系统。

  • 按完成进度推进，不按自然日期强制跳课。
  • 完成当天后自动准备下一天，减少等待。
  • 学习首页、计划页和学习页读取同一个当前学习位置。
  • 生成卡住、保存失败、缓存已存在等异常要有明确状态。
  • 反馈驱动重规划和后台分析进入后续版本。

技术方案

围绕路径状态账本、完成事件、预生成队列和状态恢复实现。

  • PathLoopState 保存当前可学位置、解锁状态和预生成任务。
  • PathEvent 记录完成、预生成、恢复和异常。
  • pre_generation 负责下一天内容生成、轮询、恢复和超时提示。
  • /api/instance/{id}/path-loop 暴露路径状态。
  • 前端轮询状态并在退出重进后恢复。

开发范式

先把状态做准，再做自动优化。

  • 状态账本独立落盘，不直接迁移主数据。
  • 完成事件幂等写入，避免重复奖励和重复预生成。
  • 缺少新状态时从旧 completion 数据懒初始化。
  • 先支持下一天预生成，再扩展到整周预生成。
  • 后台日报和自适应调整等待真实数据后再立版本。

核心问题映射

每个问题都必须对应产品需求、技术方案和验收信号，避免只写方向。

Problem Matrix
核心问题产品需求技术方案验收信号
日期和学习进度错位用户几天没学不会自动跳到后面；学习首页始终显示“当前应该继续的天”。PathLoopState 使用 completion_cursor，而不是 date_cursor；路由进入时通过 getCurrentLearningUnit(instance_id,user_id) 计算当前可学单元。断更 3 天后回到路径，仍进入未完成的 D1/D2；后续天只显示目录和锁定状态。
下一天内容没有准备用户完成一天后，系统自动准备下一天内容；下次进入优先看到“已准备好”。lesson_completed 事件创建 PreGenerateJob；队列写入 queued/running/succeeded/failed/stale；成功后写入 lesson_cache。完成 D1 后 1 分钟内出现 D2 生成任务；刷新学习首页能看到 D2 的明确状态。
生成页长时间卡住用户能看到生成是否仍在进行、是否已经完成、是否失败、是否可重试。前端轮询 job status；后端 reconcile_job_status 检查缓存、文件、任务锁和超时；超过阈值自动转 failed_timeout。不会出现“页面还在转圈但退出再进发现已完成”；超时后有重试入口和失败原因。
反馈没有影响后续学习用户点“太浅/有错/想换方向/重新生成原因”后，后续内容深度、案例和练习会变化。PathSignal 聚合 feedback、QualityReport、wrong_answers、regenerate_reason；SignalReducer 生成 next_lesson_constraints。下一天生成日志能看到使用了哪些信号；学习页能解释“因为你反馈 X，所以今天调整 Y”。
路径不会主动恢复断更用户断更后不被惩罚，也不直接进入新内容；先给一个恢复任务。inactive_days >= 阈值时创建 recovery_mode；Planner 在下一天加入轻量复习和恢复检查。断更后首页显示“先恢复一下”，并提供 5-10 分钟复习任务。
后台不知道哪里出问题管理员能看到路径级失败、等待、低质量内容和高频痛点。PathAnalyzer 每日聚合 PathEvent、PreGenerateJob、QualityReport、Feedback；生成 AdminPathReport。后台分析页可按日期查看低分内容、卡住任务、失败原因、用户反馈聚类。
旧路径数据结构不一致旧用户路径仍可打开，不因新状态机缺字段而报错。PathStateAdapter 为旧实例补默认值；读写分离，新字段缺失时懒初始化。线上旧路径打开正常；迁移脚本 dry-run 无破坏性写入。

PRD
优先级模块具体需求验收方式

P0完成事件完成一天时写入 completed_at、score_summary、outputs、feedback_summary，并触发下一天准备。刷新页面不丢完成状态；重复点击完成不会重复创建任务。
P0下一天预生成支持“准备中、已准备、准备失败、可重试、无需准备”五种状态。用户能分辨是卡住、失败还是已完成；每种状态都有对应按钮或说明。
P0任务恢复用户退出学习页或刷新后，系统能根据 job_id 和缓存恢复生成状态。退出再进入不会丢任务；已生成内容不会重复扣积分和重复生成。
P0路径级数据回流汇总 QualityReport、用户反馈、错题、产出、耗时、重生成要求和跳过行为，形成 PathSignal。下一天生成能读取 PathSignal；后台能查看信号摘要。
P1轻量自适应根据信号调整下一天的讲解深度、案例类型、练习难度、复习比例和来源偏好。系统能解释“为什么明天增加复习/降低难度/补来源”。
P1用户确认机制目标、周期、每周结构等大幅调整必须确认；讲解深度、练习难度等轻量调整可自动执行。自动调整日志可追踪；不会悄悄改变学习目标。
P1后台每日分析每天生成管理员报告：用户活跃、内容低分、卡住节点、搜索失败、生成超时、投诉/反馈聚类。后台分析页能按日期查看问题和建议处理动作。
P2路径级复盘每周结束后生成一份“本周学情复盘”，包括掌握变化、错点、下一周建议。完成一周后，学情页能看到本周结构化分析。

开发准入补强

V0.47 不是把更多自动化堆上去，而是先让路径运行状态可信、可恢复、可解释。

Readiness Gate
缺口补强动作产出物验收标准
PathLoopState 状态机不明确先定义 not_started、current_available、lesson_running、lesson_completed、next_preparing、next_ready、job_failed、recovery_needed 八类状态。状态机图 / 状态矩阵学习首页、计划页、学习页三处读取同一状态，不出现互相矛盾。
任务一致性和幂等不足所有完成、预生成、重试、保存动作都必须有 idempotency_key、cache_key 和 lock 规则。幂等规则表重复点击、刷新、退出重进不会重复生成、重复扣积分或重复奖励。
PathEvent 事件缺少最小集定义 lesson_completed、feedback_added、job_created、job_succeeded、job_failed、user_inactive、plan_adjusted、runtime_recovered。事件 schema后续学情分析和后台日报不再靠猜状态，而是消费事件。
SignalReducer 边界不清把自动调整分成轻量自动和重大确认两类：深度/练习/复习比例可自动；目标/周期/周结构必须确认。调整权限表系统能解释每次调整原因，且不会悄悄改变用户的核心学习目标。
生成完成检测不可靠新增 JobReconciler，对比任务状态、缓存文件、LessonFlow 是否存在、前端轮询状态。任务恢复规则不会再出现“页面还在质量审查，但退出再进已经生成完成”的错位。
后台没有运营视角最小后台指标包括 stuck_jobs、failed_jobs、low_quality_lessons、regenerate_reasons、feedback_clusters、inactive_paths。AdminPathReport每天能看到哪些路径卡住、低质、被重生成或用户断更。

状态机草图

路径级 Loop 的第一真相源是状态机，不是页面按钮，也不是自然日期。

State Machine
状态含义允许动作退出条件
not_started路径已创建但用户还没有开始第一天。开始 D1、查看计划、返回学习空间。用户点击开始 D1。
current_available当前天内容已经可学。进入学习、查看当周目录、查看学情。进入学习页后变为 lesson_running。
lesson_running用户正在学习当前天。保存步骤、回看已学、继续学习、退出后恢复。完成当天或用户退出。
lesson_completed当天已经完成，奖励、产出和反馈已记录。查看完成内容、触发下一天准备。PreGenerateJob 创建成功。
next_preparing下一天正在生成或质检。查看进度、离开页面、重试失败任务。任务成功、失败或超时。
next_ready下一天已生成并可进入。开始下一天、查看计划。用户开始下一天。
job_failed预生成失败或超时，原因已保存。重试、降级生成、联系后台排查。重试成功或用户放弃。
recovery_needed用户断更或状态不一致，需要先恢复。做恢复任务、重新同步状态。恢复任务完成或 JobReconciler 修复成功。

幂等与恢复规则

这些规则直接约束开发，避免路径运行中出现重复、卡死和数据错位。

Recovery
场景系统规则用户体验验收
重复点击完成同一 lesson_id + user_id + step_id 只接受一次完成事件，后续返回 already_completed。不会重复奖励积分，不会重复创建下一天任务。连续点击 5 次完成，只产生 1 条 lesson_completed。
任务成功但 UI 仍等待JobReconciler 发现 lesson_cache 存在且 QualityReport 有效时，将 job 状态改为 succeeded。刷新后直接进入已准备状态。模拟前端断线后恢复，页面不再无限显示质量审查。
任务 running 超时超过 timeout_seconds 后自动转 failed_timeout，保留 partial_trace 和 retry_payload。看到失败原因和重试按钮，而不是盲等。超时任务 1 分钟内进入可重试状态。
缓存存在但 PathLoopState 缺失读取路径时懒初始化 PathLoopState，并从已完成 lesson 反推 completion_cursor。旧路径仍能打开，当前进度不丢。旧实例 dry-run 通过，页面无报错。
下一天重复预生成unit_id + signal_hash 生成 cache_key；相同 cache_key 直接复用。不会因为刷新或重复触发导致成本翻倍。同一 unit 重复触发只生成一个有效任务。
用户改了路径目标重大目标变化创建 plan_adjustment_pending，不自动覆盖原路径。用户确认后才重规划。目标、周期、周结构变化都有确认记录。

技术方案拆解

这里说明 V0.47 需要新增哪些核心对象、接口和后台任务。

Tech Plan
层级组件职责关键字段 / 接口
状态层PathLoopState路径运行时的唯一真相源，负责当前可学位置、解锁、队列、信号摘要。instance_id、user_id、current_week、current_day、completion_cursor、unlocked_units、pending_jobs、signal_summary、updated_at。
事件层PathEvent记录路径运行中的事实，供状态机、分析和回放使用。lesson_completed、feedback_added、job_created、job_succeeded、job_failed、user_inactive、plan_adjusted。
队列层PreGenerateJob管理下一天内容生成任务，防止重复生成和无法收敛。job_id、unit_id、status、attempts、started_at、deadline_at、finished_at、error_code、cache_key。
恢复层JobReconciler检查“页面状态、任务状态、缓存文件”是否一致，修复已完成但前端仍卡住的问题。GET /api/path/jobs/{job_id}/status；reconcile_cache_exists(job_id)；timeout_to_failed(job_id)。
信号层SignalReducer把单节学习行为转成下一天可用的规划约束。quality_score、low_depth_reason、wrong_concepts、feedback_tags、preferred_source_type、regenerate_reason。
规划层NextUnitPlanner根据当前路径、信号和未学目录，生成下一天的 lesson request。build_next_request(path_state, signal_summary, next_unit_outline)。
分析层PathAnalyzer面向管理员聚合路径问题，不直接影响用户路径。daily_path_report、failure_clusters、slow_jobs、low_quality_lessons、feedback_clusters。
兼容层PathStateAdapter旧数据缺字段时懒初始化，保护线上用户数据。load_or_initialize_state(instance_id,user_id)、migrate_dry_run、schema_version。

关键流程

用事件驱动路径闭环，避免按自然日期硬推。

Flow
触发事件系统动作用户侧呈现后台记录
完成一天保存当天学习结果，创建下一天预生成任务。提示“下一天正在准备”，但用户可以离开。lesson_completed、queue_created、quality_summary。
预生成成功写入下一天 lesson cache，更新 PathLoopState。学习首页显示“下一天已准备好”。generation_done、duration、source_count、quality_score。
预生成失败保存失败原因，提供重试，不影响已完成内容。显示“准备失败，可重试”，不假装还在生成。generation_failed、error_type、retry_count。
用户反馈内容问题记录反馈，影响后续内容深度和来源策略。提示“已记录，会用于后续安排”。feedback_signal、affected_modules。
连续断更不跳课，生成恢复建议和轻量复习。回到当前天，并提示“先补一个恢复任务”。inactive_days、recovery_plan。

边界与依赖

V0.47 v1 先完成状态与预生成，质量信号驱动的自动优化留给后续。

Dependency
本版边界：V0.47 已在不依赖完整后台分析的前提下先完成状态机、完成事件、下一天预生成和恢复机制；QualityReport、PathSignal 和后台日报用于后续自适应版本。
依赖数据为什么必须有没有时的处理
QualityReport路径级 Loop 需要知道哪节内容太浅、来源弱、互动差，才能调整后续内容。只允许做状态机和任务恢复，不启用自适应策略。
LessonRuntime需要知道用户看过、选过、写过、完成过哪些步骤。只能按完成状态推进，不做细粒度学习分析。
PathSignal需要把反馈、错题、重生成原因汇总成下一天约束。下一天沿用原计划，不自动改变难度和来源偏好。
ResearchPack需要判断用户是否偏好权威文档、论文、视频或案例来源。默认沿用 V0.46 的来源策略。

本版本不做什么

把边界写清楚，避免路径级 Loop 变成一次性大重构。

Out of Scope
不做原因后续放在哪里
全自动重写整条学习路径风险太高，会破坏用户已经确认的目标和计划。后续在路径级 Loop v2 中引入“用户确认式重规划”。
跨周批量预生成全部内容成本高、容易过期，也会放大低质量内容风险。先做下一天，真实稳定后再做下一周。
复杂推送系统当前核心是路径状态和预生成，不是通知渠道。移动端推送或飞书 IM 单独立版本。
重新设计单节内容结构这是 V0.46 的职责，V0.47 只消费单节质量报告和学习信号。回到 V0.46 教学内容 Loop v1。

后续策略待真实数据确认

这些不是 V0.47 v1 的完成阻塞，而是后续自适应和后台分析版本需要继续收敛的策略参数。

Data Needed
待确认项确认依据默认策略
预生成频率单节生成耗时、积分消耗、失败率和用户打开频率。只预生成下一天，不批量预生成整周。
超时阈值V0.46 LessonBuildGraph 的 P50/P90/P99 耗时。超过 P99 + 30 秒进入 failed_timeout。
重规划触发断更天数、低分内容、错题、重生成次数、用户反馈强度。先只做轻量恢复任务，不自动重写周计划。
自动调整权限用户对自动调整的接受度和后续学习完成率。讲解深度、练习难度自动；目标、周期、周结构确认。
后台指标阈值真实 stuck_jobs、failed_jobs、low_quality_lessons 的分布。先展示绝对数量和明细，不做复杂告警。

本版收口结论

V0.47 v1 已作为独立版本完成，后续不在本版继续塞需求。

Decision
收口结论：V0.47 v1 已完成状态机、事件、幂等恢复和下一天预生成，先修复“卡住/错位/重复”的用户体验问题。自适应重规划和后台质量分析进入后续版本，等真实 QualityReport、LessonRuntime 和 PathSignal 积累后再启用。
