建立长期版本管理中心

把 LearnBuddy 的需求、技术方案、开发范式、验收和归档从散落文档中收束到项目工作台，并明确后续每期迭代都按版本号推进。

状态：已开发版本：V0.45范围：文档与治理

需求方案

解决“文档越来越多、入口混杂、版本语义不清”的问题。

  • 主入口只保留项目总览、版本管理、需求池、技术账、验收和归档。
  • 版本标签统一为已开发、待开发、待确认、方案档案。
  • 每个版本有单独三件套详情页。
  • 文档中心只做目录，不再承载版本细节。

技术方案

用静态 HTML 先建立可长期维护的治理骨架。

  • 主工作台：`LearnBuddy项目工作台.html`。
  • 版本详情：`docs/versions/` 下每版本一个页面。
  • 文档中心：只维护目录入口。
  • SPEC ADR：记录版本管理决策。

开发范式

本版本的范式是“先治理，再开发”。

  • 改文档前先明确版本语义。
  • 每个新增需求先进入需求池，再绑定版本号。
  • 每个版本开工前必须有三件套。
  • 不碰线上用户数据和运行实例。
